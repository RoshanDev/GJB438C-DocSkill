# 主文档正文、附录和工程证据的边界（0.4.1）

这是本项目的交付计量策略，不是声称 GJB 438C 规定每份文档统一页数。

正文页数/字符下限仅适用于从第一个正文章节至首个附录之前的内容。首页、签字页、修改页、目录、前言、附录、附件和自动证据登记均不计入。无论附录是否标为“规范性”，此项目均单列，不自动降低正文门槛。正文与附录同页时保守排除边界页；当前渲染器独立起页，避免混合计数。附录之后重新出现数字章节，不会重新开启正文计数。

有效正文允许必要的表格、图和代码，不能以堆叠记录代替设计解释。SRS/SSS 的逐项要求放入需求章，SDD/SSDD 的算法、状态、并发和异常放入详细设计，IDD 的字段与协议放入接口章，DBDD 的表/字段/约束放入数据库设计，STD 的可执行步骤与判据放入测试章。章末只保留追踪汇总，长日志、原始输出和补充材料置于附录或独立文件。

`gjb-*` 证据块只保留一个权威位置。Word 在原位置展示字段表，默认不再生成“附录 结构化工程证据”。不另外复制同一证据生成整表和逐字段复述。不能只把“附录”改成“第8章”，也不能循环换编号或同义改写填够字数。

历史资料的迁移顺序：备份旧稿 → 列出每个附录的用途及拥有它的正文章节 → 将必需条款/证据移动至正确章节并补充语义说明 → 删除确认冗余的副本（保留版本历史）→ 重新 review → 人工确认后 release。不能由 Agent 自填批准或伪造测试结果。

新的 volume JSON 使用 `page_count_scope: main_body_only_v1`，`body_pages` 是正文页，`appendix_start_page` 与 `appendix_pages` 独立记录。整套审计拒绝缺少该口径的旧报告。原有 Word 没有明确计数书签时应从 Markdown 重新生成，不手工填页数。`GJB_BODY` 依然绑定完整内容，排除附录计量不表示允许附录随意修改。

工具可检查结构边界和明显模板展开，不能自动证明每句事实或识别所有凑字数手法。最终还须人工语义审阅和目标 Office/字体环境的逐页版式检查。
